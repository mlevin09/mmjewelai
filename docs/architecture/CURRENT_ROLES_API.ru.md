# Backend текущих ролей (RU TRANSLATION)

ROLES-001; см. ADR 0044. Документ не означает merge/deployment или очистку общей БД.

## Runtime-контракт

Authenticated чтение:

- `GET /roles`: все активные текущие определения (21 после первого импорта).
- `GET /roles/{role_id}`: полное определение, источники, maturity, aliases и revision строки.
- `GET /roles/{role_id}/context`: контекст человеческой роли, maturity паспорта и null policy.
- `GET /ui/catalog`: девять выборов Studio в порядке конфигурации приложения;
  каждый содержит `role_id`, `name_ru`, nullable `name_en`, `revision`.

Существующий `POST /projects/{project_id}/sessions` принимает эти девять выборов. Существующие
session/text-intake/revision/question routes сохраняются; нового движка состояния или беседы нет.
Остальные канонические роли доступны внутреннему lookup, не выбору в данном Studio pilot.
Неизвестные, объединённые исторические RR ID и шесть старых ID получают `422 invalid_role`.
Отсутствующий/повреждённый каталог получает `503 role_catalog_unavailable` без raw SQL/data.
Membership организации и scope сессии обязательны и не зависят от профессии человека.

## Импорт и обновление

Миграция `0021_roles_foundation` создаёт одну новую таблицу, импортирует 21 текущую запись
и добавляет unvalidated FK с сохранением существующих сессий. Live cleanup не выполняется.
Миграция проводится отдельно разрешённым deployment-путём, не при запуске приложения.

Явный повторный импорт: установить server-side `DATABASE_URL`, затем выполнить
`python -m jewelai_persistence.roles`. Читается поставляемый seed, не Google Drive.
Импортер также принимает явно переданный полный набор 21 записей. Источники проверяются
по хешам; повреждённый импорт отклоняется транзакционно. Row locks сериализуют обновления
существующих записей; revision растёт только при изменении определения. Одинаковый повторный
импорт не меняет timestamps/revisions. Это операторская функция, не public write API.
Кэша исторических определений и legacy JSON reader нет. `data/roles/sources` содержит
доказательства/входы импорта, а не альтернативный рабочий каталог.

Черновые паспорта/persona импортированы полностью с исходными хешами. Новые английские
названия и role-specific LLM policies не выдуманы. Потребитель контекста должен сохранять
непроверенную maturity и не превращать свойства человека в авторитетные system instructions.

## Границы проверки

Локальные SQLite HTTP тесты проверяют выбор, ввод/продолжение, CAS, восстановление fresh app,
запрет чужого tenant, точность источников, обновления, повреждённые данные и idempotency.
Они не квалифицируют PostgreSQL ARRAY/JSONB, фактический Alembic и FK. PostgreSQL тест использует
существующий fresh-container/cluster/job safety gate перед DDL. Общие данные не удалялись.
Существующие записи со старыми ID сохранены, но не поддерживаются.

Оригиналы находятся внутри побайтно сохранённого `data/roles/sources/original-role-sources.zip`;
import manifest идентифицирует отдельные файлы архива. Исходные Markdown hard-break пробелы
сохранены без отключения Git whitespace checks и без изменения исходных байтов.
